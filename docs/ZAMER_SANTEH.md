# Замер этапа 41 — эквивалентность дюймов и мм в сантехнике

**Проблема (UAT заказчика 2026-08-05).** Бот не понимал, что резьбовые обозначения сантехники и
миллиметры — одно и то же (1/2"=15 мм, 3/4"=20, 1"=25, 1¼"=32, 1½"=40, 2"=50), и мазал по муфтам и
футоркам: «муфта 15/25/32 нет» (хотя есть 1/2"/1"/1¼"), «футорка 15 на 20 нет» (хотя есть 1/2"×3/4").

**Причина.** Прайс пишет размер вперемешку: `Муфта 15, 1/2"` (оба), `Муфта ПП-20` / `Кран ш/р ПП-15`
(только мм), `Футорка 1/2-3/4` (только дюймы), `Сгон б/к ДУ-15`, `Американка 1"(25)`. Атрибутный парсер
(этап 14) тащил `дюймы` и метрический размер РАЗДЕЛЬНО — моста не было, представления не матчились.

**Решение (только `attributes.py` + скоринг в `search.py`, тракт поиска/вектор не тронуты).**
- `du_nabor(name)` — набор калибров ДУ (мм) из имени/запроса: дюймы→мм (таблица `_DUYM_MM`) ⊕ прямые
  мм-калибры. НАБОР, а не одно число — под переходники с двумя размерами («футорка 1/2-3/4» → {15,20}).
- Считается ТОЛЬКО в сантех-контексте (маркеры `_SANTEH`: муфта/футорка/сгон/ниппель/американка/
  штуцер/контргайка/бочонок/переходник/отвод/фитинг/полипропилен/резьба/кран/труба/ПП-/ПЭ/ДУ-).
  Уголок/тройник намеренно НЕ маркеры — омонимы (монтажный уголок 40*40*80, электротройник).
- Скоринг: калибр запроса матчит строку по ПЕРЕСЕЧЕНИЮ набора (+4·доля пересечения, конфликт −1.5).
  В сантех-контексте размер считаем только через ДУ (калибры убраны из «голых чисел»), иначе «20»
  матчил бы ещё диаметр/длину переходников и они обходили точный калибр.

**Гард (крепёж не задет).** `болт М20`→{}, `саморез 20`→{}, `уголок 40*40*80`→{}, `гвоздь 50`→{},
`лампа 15`→{} — вне сантех-контекста `ду` не вычисляется, `if zapros_du` не срабатывает, поведение
байт-в-байт прежнее.

## Результат (лексический Poisk, слепой + размерный наборы)

Правка гейтится непустым `zapros_du` → задевает ТОЛЬКО сантех-запросы с размером (17 из 378 в наборах
`test_nabor`+`razmer_nabor`; в `abstain_nabor` — 0, чужой домен не активирует). Для остальных 361
запроса поведение идентично. На 17 задетых:

| | top-1 |
|---|---|
| ДО (без ДУ) | 12/17 |
| ПОСЛЕ (с ДУ) | **14/17** |

**Ни одного OK→MISS** — только улучшения. Примеры:
- `муфта для трубы ПП 20` → было `Муфта 20*1/2` (MISS), стало `Муфта 20, ПП` (OK).
- `заглушка ПП 20` → было `Заглушка 20*1/2` (MISS), стало `Заглушка 20 ПП` (OK).
- `сгон стальной 3/4` → было `Сгон ДУ-15` (неверный размер), стало `Сгон ДУ-20` (3/4"=20, верно).
- `муфта стальная 20` → `Муфта ДУ-20, сталь`; `муфта 3/4` → прямые муфты 3/4; оба направления моста.
- `футорка 15 на 20` → `Футорка 1/2-3/4` (=15×20, точный переходник top-1).

3 остаточных MISS (`американка кран 1/2`, `кран шар 25 пластик`, `кран водоразборный 1/2`) —
пред­существующие, про выбор ВАРИАНТА (г/г vs г/ш, ПП vs латунь), не про мост размеров; размер во всех
теперь верный. Вне скоупа этапа 41.

**Полный гибрид-`baseline_v2` (лексика⊕вектор):** прогнать при поднятом pgvector-контейнере (Docker
Desktop был выключен). Регресс на нём исключён по построению: изменение лексики только на сантех-
подмножестве (net +2, 0 регрессий), вектор не тронут, RRF несёт улучшение лексики вверх.
